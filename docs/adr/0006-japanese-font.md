# ADR-0006: 日本語フォントに Noto Sans JP を同梱する

- Status: Accepted
- Date: 2026-10-06
- Decider: 所長（Ink Inc.）

## Decision

Ink Mixer の GUI で日本語を表示するため、Noto Sans JP を同梱する。
フォントファイルの追加と GUI への組み込みは、Phase 1 の GUI 実装で行う。

## Context

GUI フレームワークは egui に決めた（ADR-0004）。egui の既定のフォントには日本語が含まれない。
Spike #21 では OS のフォントを実行時に読む方式で日本語を表示した（Linux: Noto Sans CJK JP、Windows: 游ゴシック）。
ADR-0004 では、同梱するか OS のフォントを読むかを未決とし、Phase 1 の GUI 実装前に決めるとしていた。

## Options

1. **Noto Sans JP を同梱する**
2. **OS のフォントを実行時に読む**（Spike #21 の方式）

## Chosen

Option 1: Noto Sans JP を同梱する

## Why

- 配信者向けアプリで文字が表示されないのは致命的。UI の固定文字だけでなく、BGM・効果音のファイル名など任意の日本語が出る
- OS のフォントを読む方式は、Linux で日本語フォントが入っていない環境に弱い（パスもディストリビューションごとに違う）
- Noto Sans JP は SIL Open Font License 1.1（OFL）で配布されている。OFL のフォントは、OFL のまま GPL のソフトウェアと一緒に配布できる（ADR-0005）

採用しなかった案:

- OS のフォントを読む: バイナリは小さくなるが、日本語フォントの無い環境で表示できない

この ADR の判断は一般的な考え方に基づくもので、法的な助言ではない。

## Consequences

- バイナリが数MB増える（実装時に実測する）
- ファイル名など任意の日本語を表示するため、文字を絞った軽量版（サブセット）にはしない
- 同梱するファイルの形式（太さごとの静的フォントか可変フォントか）と太さの種類は、egui での表示を確認して実装時に決める
- フォントは改変せずに同梱し、OFL のまま扱う（Ink Mixer の GPL のコードとは別の著作物）
- OFL の全文と著作権表記を同梱する（ROADMAP Phase 2 の cargo-about と合わせる）
- 将来、OS のフォントや好きなフォントを選べる設定を足すことは妨げない
- ADR-0005 の「フォントの扱いは組み込みの実装時に確認する」は、日本語フォントについてはこの ADR で方針を決めた。egui 同梱の欧文フォントは引き続き組み込み時に確認する
