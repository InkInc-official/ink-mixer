# ADR-0010: 音源フォルダ、Asset ID、索引（`library.toml`）、取り込みの規則

- Status: Accepted
- Date: 2026-10-29
- Decider: 所長（Ink Inc.）

## Decision

BGM と SE を設定に生パスで保存しないため（AGENTS.md §4 の 6、ARCHITECTURE.md §9）、Ink Mixer が持つ**音源フォルダ**と、それを台帳にする**索引**を作る。Issue #61（C）で実装する。ADR-0009 が「Asset ID の作り方、ライブラリの索引の形式は C・B で決める」と残した点を、ここで決める。

### 1. 音源フォルダ

- 場所は、`directories` の `ProjectDirs::from("", "Ink Inc", "Ink Mixer")` の **`data_local_dir()`**（これを `<root>` と呼ぶ）。Linux は `~/.local/share/inkmixer/`（`data_dir()` と同じ）、Windows は `%LOCALAPPDATA%\Ink Inc\Ink Mixer\data\`
  - Issue #61 の本文は `data_dir()` だった。Windows の `data_dir()` は `%APPDATA%`（ローミング）で、ドメイン環境などで同期の対象になりうる。数百 MB になる音源には向かないので、`data_local_dir()` にする。設定ファイルは今のまま `config_dir()` に置く
- 中身: `<root>/sounds/bgm/`、`<root>/sounds/se/`（音源。利用者に見せる）と、`<root>/library.toml`（索引。音源のフォルダの外に置く）
- **場所は設定ファイルに保存しない。** C では変えられない（既定の場所だけ）。ただし `Library::open(root)` は場所を引数に取るので、後で設定項目や引数を足しても API は変わらない
- 音源の中身は、「ボイストリガー・サウンドパッド用の効果音」と「フリー BGM」。権利の確認は使う人の責任（ADR-0008）。外部のサービスとは連携しない

### 2. Asset のモデルと ID

- Asset: ID、種類（`bgm` | `se`）、表示名、保存先（種類のフォルダからの**相対パス**）、情報（形式・サンプルレート・チャンネル数・フレーム数）、状態、`trigger_words`
- 種類は、置かれたフォルダ（`bgm/` か `se/`）で決まる。ファイルを別の種類のフォルダへ動かすと、別の Asset になる
- **ID は文字列 `"bgm-0005"`、`"se-0012"`**（種類の接頭辞 + 4 桁以上の 10 進の連番）。ARCHITECTURE.md の `asset_id = "..."` に合わせ、設定ファイルを手で読み書きできる
  - 索引が `next_id`（1 つの連番）を持ち、Asset を登録するたびに進める
  - **一度付けた ID は再利用しない。** ファイルが消えても、索引から外しても、`next_id` は戻さない
  - ID の接頭辞と種類は一致していなければならない
- 状態（使える／ファイルが無い／読めない）は**保存しない**。開いたときはファイルの有無から、再スキャンではファイルの有無と中身の確認（`probe`）から決める。**状態が「読めない」や「ファイルが無い」のものも、他と同じエントリとして索引に残る**（状態を保存しないだけで、エントリと ID は消えない）
- 設定ファイルには **Asset ID だけ**を保存する（F が任意項目として足す。`CONFIG_VERSION` は上げない）。ファイルの場所は、使うときに `Library::path_of(id)` で絶対パスにする。絶対パスは保存しない

### 3. 索引（`library.toml`）

```toml
version = 1
next_id = 13

[[asset]]
id = "se-0012"
kind = "se"
name = "拍手"                  # 表示名（既定はファイル名の拡張子を除いた部分）
path = "claps/拍手.wav"        # 種類のフォルダからの相対パス。区切りは常に "/"
trigger_words = []

[asset.info]
format = "wav"                 # "wav" | "mp3"
sample_rate = 48000
channels = 2
frames = 96000                 # ファイルが言わなければ書かない
```

- **`[asset.info]` は、一度も `probe` が成功していないファイルには書かない**（`Asset::info()` は `Option`）。`probe` が成功したことがあるファイルが、後で読めなくなった（または消えた）場合は、**最後に読めたときの情報を残す**（一覧に長さを出し続けられる）。再スキャンで `probe` が成功すれば、情報を更新する

- 保存は、`config.toml` と同じ「一時ファイル → `sync_all` → `rename`。失敗したら一時ファイルを消し、元のファイルを残す」。共通の関数にまとめ、`Config::save` もそれを使う
- 読み込み:
  - 索引が無い → 空の索引で始める（フォルダは作る。最初の変更で保存する）
  - **壊れている（TOML が読めない、`version` が無い）、または新しすぎる `version` → 開かずにエラーを返し、ファイルは上書きしない**（#42 の設定ファイルと同じ方針）。エラーの種類は型で分け、F・G が表示を選べるようにする
  - 手で直した索引の**危ないパス**は、そのエントリだけ読み飛ばす。危ないパスとは、空、`/` で始まる（絶対パス）、`\ : < > " | ?` `*` や制御文字を含む、空の要素（`a//b`、末尾の `/`）、`.` で始まる要素（`.` と `..` を含む）、`.` か空白で終わる要素、Windows が装置に使う名前（`CON`、`NUL`、`COM1`〜`COM9`、`LPT1`〜`LPT9` など。拡張子が付いていても、大文字小文字を問わず）の要素、のいずれかを持つパス。取り込みと再スキャンが見つけたファイルの名前にも、同じ規則（`path_problem`）を使う
  - 同じ ID が 2 つ、種類と接頭辞の不一致、同じ種類のフォルダで同じ相対パス（大文字小文字を区別せずに比べる）が 2 つのエントリも読み飛ばす。`[asset.info]` が読めないエントリは情報なしで、`trigger_words` が文字列の配列でないエントリは空で残す。`next_id` が最大の ID 以下なら、最大の ID + 1 に直して読む。読み飛ばしと直した値は、警告として呼び出し側に返す（`Opened.warnings`）。**読み飛ばしたエントリは、次の保存で索引から消える**（下の Consequences）
- **復旧は自動でしない。** 壊れた索引から作り直すと ID が変わり、設定の参照が切れる。手動の復旧は「索引を削除 → 再スキャン」（新しい ID が付く。表示名とトリガーワードは失われる）。`Library::reset_index(root)`（壊れた索引を退避して空にする）は、G が利用者に確認してから呼ぶ部品として用意する
  - 退避先は、同じフォルダの **`library.toml.broken`**。**既にあるときは上書きせず、`library.toml.broken-2`、`library.toml.broken-3`…と連番にする**（空いている最初の名前。上限 1,000）。退避は `rename` で行い（コピーではない）、退避した後は、索引が無い状態（空の索引で始まる）になる。退避先のパスを返す（お知らせに使う）
  - 索引が壊れていない（読める）ときに呼ばれたら、何もせずエラーにする（動いている索引を退避しない）
- **版の規則**（`CONFIG_VERSION` と同じ）：任意項目の追加では `version` を上げない。名前・意味・型を変えるとき、古い形が読めなくなるときに上げ、マイグレーションを足す。古い版のアプリが、新しい任意項目を知らずに保存すると失われる（ダウングレードは想定しない）
- 2 つのプロセス（窓と CLI）が同時に保存すると、後の保存が勝つ。ロックは作らない

### 4. 取り込み＝フォルダへコピー

元の場所に依存しない（ARCHITECTURE.md §9）。ブロッキングの処理なので、呼び出し側はワーカースレッドから呼ぶ。

1. 元が通常のファイルであること（ディレクトリ・存在しない → エラー）。シンボリックリンクはたどってコピーする。ライブラリのフォルダの中のファイルは、コピーせず `AlreadyInLibrary`（「更新」で反映する）
2. 拡張子が `wav` / `mp3`（大文字小文字を区別しない）でなければ断る（`UnsupportedFormat`）。中身を `probe` して、音声でなければ断る（`NotAudio`）。ファイルが読めなければ `Unreadable`（コピー中に元が読めなくなったときの `Source` とは別）。どれも、ファイルは作らず、お知らせに使える形で返す
3. SE で、長さが分かって 60 秒を超えるなら断り（`TooLongForSe`）、BGM に登録するよう案内できる形にする。長さが分からない MP3 は通す（読み込み時の上限が守る）。上限の 60 秒は `ink-core` の定数にする
4. コピー先の名前は元のファイル名。同じ名前が既にある場合は、**大文字小文字を区別せずに**調べる（Windows と Linux で結果を揃える）。**中身が同じなら、コピーせず既存の Asset を返す**（`AlreadyThere`）。「中身が同じ」の判定は、**まずファイルのサイズを比べ**（違えば別の中身）、**同じサイズのときだけ、先頭から順にバイトを比べる**（ストリーム。固定サイズのバッファで読み、メモリは一定。違うバイトが見つかった時点で止める。ハッシュは持たない）。**違えば `名前 (2).拡張子`、`(3)`…** にする（上限 1,000）。255 バイトを超える名前は語幹を切り詰める。**Windows で使えない名前**は、安全な形にする（下の「名前の整え方」）。UTF-8 でない名前（Linux）は断る。**ファイルが無くなった Asset でも、その名前は塞がったまま**で、次の番号に進む。**手で入れたまま走査していないファイル**（索引に無い）は Asset ではないので、中身が同じでも `AlreadyThere` にせず、名前を塞ぐだけで次の番号に進む
5. **違う名前で中身が同じファイルは、別の Asset にする。** 中身の照合・ハッシュは持たない
6. コピーは、コピー先のフォルダの中の一時ファイル（`.import-<n>.tmp`。使われていない最小の `n`。クラッシュで残ったものには触らない）へ `io::copy`（ストリーム。巨大なファイルでもメモリは一定。元の読み取りの失敗と先の書き込みの失敗は見分ける）→ `sync_all` → **`hard_link` で最終の名前を付けて**、一時ファイルを消す。`hard_link` は、先に同名があれば `AlreadyExists` で失敗し、上書きしない（Linux と Windows で同じ）。競合したら次の番号へ進む。**`rename` は使わない。Rust の `fs::rename` は Windows で既存のファイルを置き換えるため**（この ADR の最初の版は「Windows の `rename` は上書きしない」と書いていたが、誤りだった）。ハードリンクが使えないファイルシステム（ネットワークドライブなど）では、名前の存在を確かめてから `rename` する。確認と `rename` の間の一瞬の競合は理論上ありうる（単独の利用者のアプリなので許容）
7. 索引に足して保存する。**保存に失敗したら、コピーしたファイルを消してエラーにする**（登録されないファイルを残さない）
8. どの段階で失敗しても一時ファイルを消す。元のファイルには触れない。エラーは、元が読めない（`Source`）、先が書けない（`Destination`）、容量不足（`DiskFull`。`StorageFull` と `QuotaExceeded`）を見分けられる。名前の番号が尽きたら `TooManyNames`。ID が作れない（番号が尽きた）、索引が保存できない、は `Library(...)` に包んで返す。**ID は最初に作るが、索引が保存できてから渡す**（失敗した取り込みは ID を使わない）
9. 巨大なファイルの上限は設けない（BGM は長さの上限なし）。進捗・取り消しは C では持たない

**名前の整え方**（取り込むときのコピー先の名前。語幹は、最後の `.` より前）:

- `\ / : < > " | ? *` と制御文字は `_` にする
- 語幹の先頭の `.` は `_` にする（`.` で始まる名前は隠しファイルで、走査が無視するため）。空の語幹は `_` にする
- 語幹の末尾の `.` と空白は `_` にする（Windows が落とすため）
- Windows が装置に使う名前（`CON`、`NUL`、`COM1` など。`con.v2.wav` のように拡張子の前に `.` があっても同じ）になる名前には、先頭に `_` を足す
- 255 バイトを超えるときは、拡張子と ` (n)` が収まるように、語幹を**文字の境界で**切り詰める
- 拡張子は、元の大文字小文字のまま
- 整えた名前は、いつも `path_problem` を通る（取り込んだファイルを走査が読み飛ばさない）

### 5. 再スキャン（フォルダに直接入れたファイルの反映）

- 利用者の操作（G の「更新」）で行う。自動の見張りは作らない
- 見る範囲は、`bgm/` と `se/` の**中のすべて**（サブフォルダを含む。深さ 8 まで。**シンボリックリンクはたどらない**）。名前が `.` で始まるもの、取り込みの一時ファイル（`.import-*.tmp`）は無視する
- 候補は拡張子（`wav`、`mp3`）で絞り、中身は `probe` で決める。**既存の Asset も毎回 `probe` し直す**（変更されたファイルを拾う。サイズや更新時刻での省略はしない）
  - 索引に無い候補のファイル → 新しい Asset。`probe` が失敗したら、**状態「読めない」のエントリとして索引に登録する**（情報は無い。状態そのものは保存しないが、エントリと ID は残る）。直って `probe` が成功すれば、同じ ID で「使える」に戻り、情報が入る
  - 索引にあるファイルが読めなくなった → 状態「読めない」。エントリ・ID・最後に読めたときの情報は残す
  - 索引にあるがファイルが無い → 状態「ファイルが無い」。**エントリと ID は残す。索引から黙って消さない**
  - 「ファイルが無い」のものにファイルが戻った → 同じ ID で「使える」に戻る
  - 候補でないファイル、UTF-8 でない名前、危ない名前、リンク、深すぎるフォルダ、読めないフォルダ、既存の Asset と大文字小文字だけ違う名前は、取り込まず、**理由つきで返す**（`SkipReason`: `UnsupportedExtension`、`NameNotUtf8`、`UnsafeName`、`TooDeep`、`Symlink`、`NotReadable`、`CaseConflict`）
  - 走査で見つからなかった既存の Asset（深すぎる、リンクの先など）は、`metadata` でファイルがあるかを確かめてから `Missing` にする（黙って `Missing` にしない）
  - 走査の順序は、種類 → 小文字にした相対パス（同じなら元のまま）。新しい ID の付き方が、ファイルシステムの列挙の順で変わらない
  - 索引に書く内容（新しい Asset、`info` の変化）が変わったときだけ、最後に 1 回保存する。状態だけの変化では保存しない。保存に失敗したら、`Library` は走査の前のままで、ID も渡さない
  - **`ScanReport` は、その走査の間に変わったものだけを返す**（遷移の報告）。状態は保存しないので、呼ばれるたびに開き直す CLI（`ink-mixer library scan`）は、いま「ファイルが無い」「読めない」ものを現在の状態で補って報告する。窓（G）は同じ `Library` を持ち続けるので、遷移の報告で足りる
- **リネーム・移動の自動の付け替え（relink）は作らない。** 古いパスは「ファイルが無い」、新しいパスは新しい Asset（新しい ID）になる。付け替えには中身の指紋を索引に持つ必要があり、直接入れたファイルを一度全部読むことになる。困ったら別の Issue にする

### 6. 対応形式と情報

- Phase 2 の形式は WAV と MP3
- 保持する情報は、形式・サンプルレート・チャンネル数・フレーム数（`Option`）。長さは保存せず、フレーム数とレートから出す。MP3 のフレーム数は、LAME タグがあればタグを除いた値（`probe` の値のまま）
- **`ink-core` は `probe` を呼ばない**（コーデックを持たない。ADR-0009）。`scan` と `import` は、呼び出し側が渡す関数で情報を得る。`ink-media` が `asset_info(path)` を提供し、アプリがそれを渡す。`AssetInfo` は `ink-core` の独自の型で、`ink-media` がそれを作る（依存の向きは `ink-media → ink-core` のまま）

### 7. `trigger_words` の予約

- すべての Asset が `trigger_words`（文字列の配列）を持つ。索引には空でも毎回書く（`trigger_words = []`）。キーの無い古い索引は空として読む
- C は**保存と読み書きだけ**（`set_trigger_words` は検査しない）。カタカナの検証、重複の検査、1 つの SE に複数のワードを付けられるかは I（#67）が決める。索引の `version` は上げない

### 8. F・G・I との境界

| 使う側 | 使うもの | 守ること |
|---|---|---|
| F（ミキサー画面） | `assets()`、`path_of(id)` | 設定には Asset ID だけを保存する。ID が無い・ファイルが無いときは「未選択」に戻す（落とさない）。BGM は `path_of` を `SoundStream::open` へ、SE は `load_sound` へ渡す。**`info()` が `None` の場合（一度も読めていない。長さを出せない）を扱う**（長さの欄を空にするなど。落とさない） |
| G（取り込みページ） | `import`、`scan`、`folder(kind)`、`forget_missing`、`reset_index` | `open` が返す警告（`Opened.warnings`）をお知らせに出す（読み飛ばしたエントリは次の保存で消えることも添える）。`import` と `scan` はワーカースレッドから呼ぶ。「ライブラリから外す」は、ファイルが無いものに限って `forget_missing` を使う（**状態が「ファイルが無い」以外のものに呼ぶと `NotMissing` を返し、何も変えない。** 知らない ID は `UnknownAsset`）。ファイルがあるものを外す（ファイルも消す／索引から外すだけ）は G が決める。**索引から外すだけだと、次の更新で新しい ID で再登録される。** 一覧では、**`info()` が `None` の場合（長さを出せない）を扱う** |
| I（トリガーワード） | `set_trigger_words`、`Asset::trigger_words` | 検証は I |

`Library` は `Send`（ワーカーに渡せる）で、`Sync` は求めない。

## Context

- 音源は今は `run --bgm <FILE>` のようにパスで渡している。ARCHITECTURE.md §9 は、設定に絶対パスを保存し続けず、Asset として登録し、Asset ID を参照すると決めている。取り込みは、フォルダへコピーする（元の場所に依存しない）
- ADR-0009 は、Asset のモデルとライブラリを `ink-core`（コーデックを使わない）に置き、ファイルの情報はアプリが `ink-media` で調べて渡す、と決めた。ID の作り方と索引の形式は C で決めると残した
- 設定ファイル（`config.toml`）には、#42 で「壊れた・新しすぎるファイルは上書きしない」「原子的な保存」の方針が入っている。索引にも同じ方針を使う
- ADR-0008 により、外部のサービスとは連携しない。音源は利用者が権利を確認したファイルを入れる

## Options

フォルダの場所：

1. `data_dir()`（Windows では `%APPDATA%`、ローミング）
2. **`data_local_dir()`**（Windows では `%LOCALAPPDATA%`）
3. 利用者が選べる（設定に場所を保存する）

Asset ID：

1. **種類つきの連番**（`"se-0012"`）
2. 種類なしの数字
3. 中身のハッシュ
4. UUID

索引が壊れたとき：

1. 自動で退避して作り直す
2. **開かずにエラーで止め、利用者に任せる**（作り直す部品は用意する）

リネーム・移動：

1. 中身の指紋で自動的に付け替える
2. **付け替えない**（古い ID は「ファイルが無い」、新しいパスは新しい ID）

## Chosen

フォルダの場所は Option 2、ID は Option 1、壊れた索引は Option 2、リネーム・移動は Option 2。

## Why

- `data_local_dir()`：Linux は同じ。Windows では、大きな音源がローミングの同期の対象になりにくい。場所を引数にしておけば、後で利用者が選べるようにしても API は変わらない
- 種類つきの連番：Issue #61 の案どおり。読みやすく、設定ファイルを手で直せる。種類の取り違えを接頭辞で検出できる。ハッシュは、中身が変わると別の ID になり、巨大な BGM を一度全部読む必要がある。UUID は手で読めない。索引が無くなると同じ曲に別の ID が付くのは、連番と同じ
- 索引を音源のフォルダの外・データのフォルダに置く：フォルダごとの移動やバックアップで ID が保たれる。設定（端末ごとの好み）と台帳（音源）を分ける
- 壊れた索引を自動で作り直さない：ID が変わると、設定の参照が切れる。黙って作り直さない（#42 と同じ）
- relink を作らない：中身の指紋を索引に持つ必要があり、直接入れたファイルを一度全部読む。割り切りで始める
- 同名で中身が同じなら `AlreadyThere`：同じファイルを 2 度ドロップしても、重複した Asset が増えない。照合はコピー先の既存ファイルとの比較だけで済む
- 大文字小文字を区別せずに名前を調べる：Windows の名前の扱いに合わせ、Linux でも同じ結果にする。同じフォルダを OS 間で持ち運んでも壊れない
- `probe` を関数で受け取る：`ink-core` が symphonia を持たない（ADR-0009）。テストでは偽の関数を使える
- 新しい crate は作らない：ADR-0009 のとおり、`ink-assets` は必要になってから分ける

## Consequences

- `ink-core` に Asset のモデル、索引、ライブラリ、取り込みが入る（新しい外部の依存は無い）。`ink-media` に `asset_info` が入る。アプリに `ink-mixer library …` の最小のコマンド（`path`、`list`、`scan`、`import`。`--library-dir` で場所を差し替えられる。検証・テスト用）が入る。窓（F・G）はまだ使わない
- **リネームすると ID が変わる。** 古い ID を参照する設定は「ファイルが無い」になる。F は「未選択」に戻す
- **索引から外すだけでは、次の更新で新しい ID で再登録される。** 外す操作は G が決める
- 手動の復旧（索引を削除、または退避）では、ID・表示名・トリガーワードが失われる。壊れた索引は `ink-mixer library` が上書きも退避もせず、手で `library.toml.broken` などの別名に移す手順を案内する（移したファイルは消さない）
- **索引の警告で読み飛ばしたエントリは、次の保存で索引から消える。** 保存は今あるエントリだけを書き、読んだファイルの写しは持たない。手で直した索引の誤りを知らせる機会は、`open` が返す警告だけになる。退避の機能は作らない（G は警告を利用者に見せる）
- **切れたファイル（ヘッダが言うより短いファイル）は、`asset_info` がヘッダの長さを返す。** 中身は読まないため。SE の 60 秒の判定もヘッダの長さで行う。切れたファイルは、終わりまで再生される（`ink-media` の既存の方針）。取り込みの時点で切れを見つけるには、デコードして長さを確かめる必要があり、C では作らない
- 同時に 2 つのプロセスが保存すると、後の保存が勝つ
- Windows で確認する項目（`%LOCALAPPDATA%` の場所、`hard_link` と `rename` への切り替え、疎ファイルが使えない場合の大きなファイル、260 文字を超えるパス、使えないファイル名と予約名、大文字小文字だけ違う名前、日本語名と PowerShell、ネットワークドライブ、権限のないフォルダ、ジャンクションとリンク、壊れた索引が上書きされないこと）を #33 に追記する
- ARCHITECTURE.md §9 の `source_path` は、種類のフォルダからの相対パスにする（この ADR の反映）
- 音声スレッドは触らない
