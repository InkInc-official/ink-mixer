# ADR-0008: 外部のサービスとは連携を作らず、中立な入口だけを作る

- Status: Accepted
- Date: 2026-10-15
- Decider: 所長（Ink Inc.）

## Decision

Ink Mixer は、外部のサービスとの**連携**を作らない。**中立な入口**は作ってよい。

- 連携: Ink Mixer が特定のサービスを知っていて、音を取りに行くもの（YouTube の URL 再生、Spotify 連携など）
- 中立な入口: Ink Mixer は中身を知らず、つながれた音を混ぜるだけのもの（入力端子と同じ）

BGM・SE は、フリー BGM などの音源ファイルを Ink Mixer のフォルダに入れて登録するのを原則とする。
抜け道（マイクで流す、OS 側で他のアプリの音と混ざる、など）は、技術で塞がない。
流す音の権利の確認は、使う人の責任とする（配信サービスの規約にも従う）。

## Context

配信者は BGM や効果音を使う。Phase 2 の Sound Library / Sound Pad で音源を扱う（ARCHITECTURE.md §9、§10）。
これまでの ARCHITECTURE.md には、BGM の「将来」に Cloud/streaming source という記述があり、外部のサービスから音を取り込むかどうかが決まっていなかった。
また、Phase 4 の「PC 内のアプリの音の取り込み」や、将来の「外部入力チャンネル」は、特定のサービスを知らずに音を受け取るもので、連携と同じに扱うかどうかを決める必要があった。

## Options

1. **連携を作る**（特定のサービスから音を取りに行く機能を持つ）
2. **連携は作らず、中立な入口と音源ファイルだけにする**
3. **抜け道も技術で塞ぐ**（マイクで流す、他のアプリの音を混ぜる、などもできなくする）

## Chosen

Option 2: 連携は作らず、中立な入口と音源ファイルだけにする

## Why

- 抜け道は技術で塞げない。塞ごうとしても、使い勝手を下げるだけになる（所長の判断）
- 流す音の権利の確認は、使う人の責任とする。Ink Mixer が、音の出どころや許諾の有無を判断することはしない（所長の判断）

次の 2 点は、判断の理由として私（Claude Code）が案として書いたもの。所長が確認し、直す。

- 連携を作ると、そのサービスの規約や仕様の変更に、Ink Mixer が左右される
- 連携を作ると、Ink Mixer がそのサービスの音を扱う側になり、権利の問題を Ink Mixer が持ち込む形になる

採用しなかった案:

- 連携を作る: 上の 2 点の理由で採らない
- 抜け道も塞ぐ: 技術的に塞げず、使い勝手を下げるだけ

この ADR の判断は一般的な考え方に基づくもので、法的な助言ではない。

## Consequences

- 機能要望の判断の基準になる。特定のサービスを知っている機能は作らない。知らずに、つながれた音を混ぜるだけなら作ってよい
- BGM・SE を使うには、権利を確認した音源ファイルを Ink Mixer のフォルダに入れる必要がある。取り込みは、フォルダへのコピーとする（ARCHITECTURE.md §9）
- README に、音源についての案内（配信の許諾がある音源の例）を載せる
- Phase 4 の「PC 内のアプリの音の取り込み」と、将来の「外部入力チャンネル」は、中立な入口として扱う。作るときに、それぞれ別の ADR を起票する
- ARCHITECTURE.md §10 の「Cloud/streaming source」は削除した
