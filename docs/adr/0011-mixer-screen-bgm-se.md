# ADR-0011: ミキサー画面の BGM と SE（配置、設定の形、セッションの作り直し、SE ローダー）

- Status: Accepted
- Date: 2026-10-30
- Decider: 所長（Ink Inc.）

## Decision

Phase 2 の部品（SE：#62、BGM：#63、音源フォルダとライブラリ：#61）を、ミキサー画面から操作できるようにする。Issue #64（F）で実装する。ADR-0009 が「窓がどう使うか」を残した点と、ADR-0010 の §8 の F の約束を、ここで形にする。

### 1. 画面の配置

- 1 段目：ストリップ 4 本（MIC・BGM・SE・マスター。ARCHITECTURE.md §7 の順）。既存の `Strip`（#40）をそのまま使う。高さは約 320 pt で固定、幅は 1 本約 134 pt
- 2 段目：ライブラリの行（読み直すボタン、ライブラリが使えないときの案内）と、BGM の操作（曲の選択、再生・一時停止・停止、位置と長さ、ループ）。幅は伸び縮みし、最小は約 180 pt
- 3 段目：Sound Pad（4 × 2 = 8 個、`PAD_COUNT`）。重ねの扱いは全体で 1 つ（重ねて鳴らす／止めて頭から／鳴っていれば無視）。「全部止める」
- 中央は**縦スクロールだけ**（`ScrollArea::vertical`、`auto_shrink` は切って幅いっぱい）。横スクロールは使わない。窓の最小は 720×480、既定は 900×640。720 pt の幅でストリップとパッドが崩れないことを、テストで実測して固定している
- 一時停止のボタンに `⏸` は使わない（同梱の Noto Sans JP に字形が無い。ADR-0006）。`▶` と `■` は使える

### 2. 窓は `Bgm` と `SeController` を持たない

- 窓が持つのは、Asset ID・フラグ・数値だけ。毎フレーム `session.bgm()` と `session.se_mut()` を順に借りる
- `InkMixerApp` では `session` を `sounds` より前に宣言する。セッションを落とす場所（停止、デバイス切替、エラー）がどこでも、ADR-0009 の破棄順序（`input`、`output`、`se`、`bgm` の順）が崩れない
- 判断（どの状態か、何を表示するか、どの失敗か）は egui を使わない `sound_state.rs` に置く。描画（`gui/bgm_strip.rs`、`gui/sound_pad.rs`）は薄くする

### 3. 設定ファイルに足す項目（Asset ID と数値だけ）

`CONFIG_VERSION` は 1 のまま（すべて任意項目。ADR-0010 の版の規則）。

```toml
[mixer]                 # 既存。BGM と SE のレベルとミュートを足す
bgm_db = -6.0
bgm_muted = false
se_db = 0.0
se_muted = false

[bgm]                   # 選んだ曲とループ
asset = "bgm-0005"
loop = true

[sound_pad]
policy = "overlap"      # overlap | restart | ignore

[[sound_pad.pad]]
slot = 0
asset = "se-0012"
gain_db = -3.0
```

- パスは保存しない（保存したファイルに `/`・`\`・`sounds` が現れないことをテストで確かめる）。再生位置と再生中かどうかも保存しない
- ID は文字列で持ち、読むときに `AssetId` にする。ID が壊れていても設定全体の読み込みは失敗しない
- 読み出しのとき、使えない項目はその項目だけ捨てて警告する：NaN・無限大、ID の形が違う、種類違い（`bgm` に `se-…`、パッドに `bgm-…`）、`slot` が負または `PAD_COUNT` 以上、同じ `slot` の 2 つ目、知らない `policy`。TOML の型そのものが違う場合は、これまでと同じく設定が読めず、保存は止まる（上書きしない）
- **ライブラリに無い ID、ファイルが無い ID は、保存で消さない。** 画面には「見つかりません」などと出し、ユーザーが選び直したときだけ置き換える（デバイスの扱いと同じ）。ライブラリが使えない間も、SE ローダーが起動しなくて窓に音の部分が無い間も、保存済みの曲とパッドは保たれる（音の部分が無い間は、選択を設定に渡さない）
- 起動時の音量：BGM と SE は**保存した値のまま**戻す（起動した時点では何も鳴らさないため）。MASTER は今までどおり −12 dB を上限にする

### 4. セッションの作り直し（デバイス切替、再開、エラーからの復帰）

- 窓のセッションは `SessionOptions { bgm: true }`（定数 `SESSION_OPTIONS`）で開始する
- **BGM は止まって頭に戻る。** 再生位置と再生中の状態は引き継がない（シークの部品が無く、デバイスを替えた直後に突然鳴らさない）。ループと選曲は窓の状態から入れ直し、音量とミュートは `MixerControl` に残る
- 止まる前に再生中だったときだけ、注意を 1 回出す。停止ボタンで落としたときは出さない。セッションの開始に失敗しても「再生中だった」記憶は保ち、次に成功した開始で注意を出す
- SE は、新しい出力レートで 1 本ずつ読み直す（ADR-0009）。読み込み中のパッドは鳴らせない

### 5. SE の読み込み（`ink-se-loader`）

- 専用スレッドで 1 本ずつ読む（8 本ぶんを UI スレッドで読むと数百 ms 止まりうる）。結果が出たら `request_repaint` で窓を起こす。待つための再描画のポーリングはしない
- 結果は `ticket` で照合し、古い（選び直し、セッションの作り直し、レート違い）結果は捨てる。`set_sound` は UI スレッドで行い、`Arc` も UI スレッドで落とす（音声スレッドでは落とさない。ADR-0009）
- 断る条件（パッドの下に日本語で出す。ホバーに英語の詳細）：60 秒超（読む前に `Asset::info()` で、分からなければ読んだあとで）、合計 256 MiB 超、ファイルが無い、読めない、音声でない
- 読み込みの時間とスキップしたパケット数は `PadBank::poll` がログに出す（`debug!`。スキップがあれば `warn!`）。UI スレッドで、リアルタイムの処理ではない

### 6. BGM の失敗の届け方

- `Bgm::take_error` を、UI の `ui()` の先頭で毎フレーム読む（読まないと見えない。ADR-0009 の制限 3）。失敗は日本語の文（種類で分ける）と英語の詳細で出し、次の停止か曲の選び直しで消える
- 再描画：4 本のストリップのどれかのメーターが動いている間は fps の上限で描く。再生中だけ 250 ms ごとに位置の更新を要求する。それ以外は、音声が動いている間の 500 ms の確認（`QUIET_CHECK`）で足りる。**止まっているときに再描画を要求しない**（ADR-0004）。失敗は再生中なら約 250 ms、そうでなければ約 500 ms で UI に届く

### 7. ライブラリを開く

- 窓の起動で `LibraryView::open` が `Library::open` を呼ぶ。**索引が使えるとき（正常、または無い）だけ**、空の `sounds/bgm`・`sounds/se` を作る（ADR-0010 の §3「フォルダは作る」）。**索引は書かない**（最初の変更、つまり取り込みで書く）
- 壊れた索引・新しすぎる版は、開かず・書かず・フォルダも作らない。赤い枠で、索引を `library.toml.broken` などの別の名前へ移す手順を案内する（消さないよう添える）。曲とパッドの選択は残る
- 「ライブラリを読み直す」ボタンは、索引を開き直すだけ（取り込みも再スキャンもしない。それは G：#65）。読み直しのとき、**失敗しているパッドだけ**を読み直す（使えているパッドは読み直さない）

### 8. パッドの数

- `PAD_COUNT = 8`（4 × 2）。置き場は 64 まで使えるが、8 で始める
- 保存を読むとき、`PAD_COUNT` 以上の `slot` は警告して捨てる

## Context

- 画面は MIC と MASTER だけで、BGM と SE は `ink-mixer run --bgm/--se` にパスを渡して鳴らすしかなかった。Phase 2 の完了条件（MIC + BGM + SE の同時出力）を、人が確かめる最初の機会が F
- ADR-0009 が破棄順序とワーカーの作りを、ADR-0010 がライブラリと設定の約束を決めた。窓はそれを壊さず、使う側に徹する
- 低スペック（RAM 8GB）の創作PCを基準にする。止まっているときの CPU を増やさない（ADR-0004）
- 成功するセッションをアプリ側のテストでは作れない（`ink-backend` のストリームは外から作れず、`FakeBackend` は「開けない」）

## Options

配置：

1. **2 段（ストリップの段と、BGM の操作の段）＋ Sound Pad の段、縦スクロール**
2. 1 段に BGM の操作もストリップの右に並べる（最小幅が約 1,000 pt になる）
3. ストリップを細くして 1 段に詰める（フェーダーが小さくなる）

範囲外のパッド（`PAD_COUNT` 以上の `slot`）：

1. **読むときに捨てる**
2. 保存で保ち続ける（見えない設定が残る）

デバイス切替のあとの BGM：

1. **止めて頭に戻す**
2. 頭から自動で再生し直す

SE の読み込み：

1. **専用スレッドで 1 本ずつ**
2. UI スレッドで同期する（切替の直後に固まる）

## Chosen

配置は Option 1、範囲外のパッドは Option 1（捨てる）、デバイス切替は Option 1、SE の読み込みは Option 1。

## Why

- 配置：最小幅 720 pt で崩れない。幅に左右されるのは BGM の操作だけ。窓を広げれば、操作の幅が伸びる。横スクロールは操作を隠すので使わない
- 範囲外を捨てる：見えない設定が保存に残り続けるより、警告して捨てるほうが分かりやすい。パッドの数を増やすときは `PAD_COUNT` を変え、移行を考える
- 頭に戻す：シークの部品が無い。切替の直後に突然鳴り出すと、配信中は事故になる
- 専用スレッド：UI を固めない。デバイス切替の直後でも、画面とメーターが動く
- 判断を `sound_state.rs` に置く：egui を使わずにテストできる。描画は薄い

## Consequences

- **`PAD_COUNT` を減らす、または古い版に戻すと、範囲外の割り当ては保存で失われる。** 読むときに捨て、次の保存では書かないため。増やす側（8 → 12 など）は、古い設定がそのまま読める
- **`Unreadable` の文が指す「取り込みページの更新（再スキャン）」のページの名前は、G（#65）の実装後に決まる。** 今の文は仮の呼び名で、G で実際の名前に合わせて直す（#65 に確認のコメントを送信済み）。文は `sound_state.rs` の `unusable_hint_ja` の 1 か所にある
- **`ui()` の本体と実セッションの経路は、自動テストで確かめていない。** `ui()` の中の呼び出し順（`poll` が先頭か、再描画の予約）、`start_selected` の成功、`check_session` の異常終了、`run` で `cc.egui_ctx` を `wake` に渡すこと、クリックとホバー、`ScrollArea` の `auto_shrink` の効き方。実機の確認項目として #33 に書く。`start_audio` と窓の開始が BGM つきで始めること（`SESSION_OPTIONS`）は、定数をテストで固定したが、2 か所がその定数を使うことまではテストで確かめていない
- **画面に合わせて窓を小さくする機能は、この PR に入れない。** 既定の 900×640 は、1366×768（100%）の画面には収まるが、125% の表示（論理サイズが約 1093×614 pt）では収まらない。最初のフレームでモニターの大きさを見て窓を縮める案は、別の Issue（#77）にする。中央が縦スクロールなので、小さい窓でも使える
- ADR-0010 の「フォルダは作る」を、窓の起動でも行う。索引が使えるときだけで、索引は書かない。壊れた索引のときは、フォルダも作らない
- 読み込みの時間とスキップしたパケット数が、ログに出る（`debug!`。スキップがあれば `warn!`）。このログの出方は、テストでは確かめていない
- `AudioSession::start`（BGM なしの近道）は、窓も `run` も `start_with` を使うようになったので削除した
- シーク、ホットキー、パッドの追加と並べ替え、取り込みとトリガーワードの UI は、この ADR の範囲外（G：#65、I：#67 など）
- Windows で確認する項目（パスの区切り、日本語・空白の名前、`%LOCALAPPDATA%`、44.1 kHz と 96 kHz のデバイスでの BGM・SE のレート変換、再生中のファイルを消す・名前を変える、1366×768（100%・125%）での窓の大きさ、CPU・GPU）を #33 に追記する
- 音声スレッドは触らない
